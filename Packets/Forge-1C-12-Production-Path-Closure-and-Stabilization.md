## 4. Provenance, identity, map, and prompt assertions

### Provenance and review

- Required malformed source candidates fail visibly rather than disappearing.
- Only accepted/applied candidates contribute reviewed source state.
- The accepted opening aim resolves to its exact registered source, evidence, candidate, character, text, and current revision.
- Placement application retains provenance in its proper ledger and never inside `presenceDisposition`.
- Missing registry, fake/pattern-shaped IDs, cross-source evidence, unrelated real evidence, rejected/staged candidates, and stale revisions all fail readiness and direct compilation.

### Identity and intent

- One stable `userCharacterId` survives import, review, export, ingress, Engine Setup, session initialization, presence, turn context, and prompt construction.
- The player begins at the explicit start node and receives the accepted opening aim once as sovereign historical orientation.
- The accepted aim creates no player pursuit, activity opportunity, internal decision, forced action, or Autopilot authority.
- A parallel `NONE_DECLARED` path reaches the actual prompt without any synthetic or legacy substitute.
- The reviewed non-user pursuit seeds only its existing HG owner.
- The no-readable-intent character has no fabricated pursuit or independent initiative merely to satisfy export.

### Map and recovery

- Main runtime nodes equal the four authored rich node definitions.
- The exact explicit `startingNodeId` survives every boundary.
- Directed exits match only authored directions.
- Offstage/nonlocal cast are absent from local presence as appropriate.
- The expandable anchor is absent from opening nodes, exits, and presence.
- Missing rich-map start fails before Engine initialization; the first node is never substituted.
- A transient Architect failure retries exact retained input and succeeds.
- A deterministic binding/identity failure preserves the correction and offers context recovery, not futile Retry.

### Containment

- Provider refusal/failure metadata and rejected proposals remain outside draft, Blueprint, Engine context, prompt, story state, telemetry canon, and ordinary exports.
- Retake/refusal behavior at touched Engine boundaries remains unchanged.
