# The Terror Machine — Forge 1C-4
## Blueprint-to-Engine Compatibility and Stabilization

### Dependency

Begin only after Forge 1C-1 through 1C-3 pass their focused gates. Implement cumulatively against that state.

This is the only packet in the series that owns the integrated vertical proof and broad stabilization run.

---

## Objective

Prove that the active Forge can produce a reference-derived, reviewed, immutable Blueprint which the active Engine loads and executes without:

- Architect correction failure;
- invalid source/cast identity binding;
- fallback empty-room topology;
- implicit first-array-node disagreement;
- silent cast co-location;
- unresolved opening motivation;
- invented user intent; or
- schema incompatibility between Forge export, Blueprint normalization, Engine setup, session initialization, and first-turn context.

This packet closes Forge 1C only. It does not by itself close the separately reviewed HG1 ratifier/forensics findings.

---

## 1. One real vertical integration fixture

Create a deterministic representative reference-analysis fixture. It may mock provider output, but it must enter through the same strict document-analysis and Architect response contracts used in production.

The fixture must include:

- a powerful source-derived non-user entity with clearly evidenced topology-altering authority;
- a queued Architect question about that authority;
- a user correction which directly confirms the source fact;
- a compact main map with multiple story-important spaces and directed connections;
- at least one optional expandable-space anchor that is not instantiated at opening;
- explicit `startingNodeId`;
- a selected user-controlled character at the opening node;
- at least one non-user cast member placed at another main node;
- at least one offstage tertiary/quaternary character;
- a source-derived default opening aim explicitly accepted for the selected user character;
- a source-derived reviewed non-user pursuit; and
- at least one non-user **No readable intent** review.

Avoid using any prohibited project names in fixture data.

## 2. Drive the actual production chain

The proof must execute the active boundaries in order:

1. normalize a document extraction response through `validateAndNormalizeDocumentAnalysis` or its successor;
2. register source analysis and binding through the active Forge path;
3. submit the user's Architect correction through the actual request builder and route contract;
4. receive a typed resolution proposal;
5. explicitly apply the resolution and accepted source candidates to canonical `forgeDraft`;
6. review the map, placements, player aim, NPC pursuit, and No readable intent state;
7. run `validateForgeExportReadiness`;
8. capture the immutable revision-bound Forge review artifact;
9. serialize and reparse the artifact through the public Blueprint normalization/ingress schema;
10. resolve player binding through Engine Setup logic;
11. initialize both active stores through the canonical session path;
12. compile the exact spatial graph and cast-presence seed;
13. build the first actual `EngineTurnContext`; and
14. pass the context through request schema validation for `/api/turn` without invoking a live model.

Do not hand-construct a post-Forge Blueprint or post-initialization context for the central proof. Helper-level unit tests remain useful, but they do not satisfy this integration requirement.

If UI orchestration makes one single test impractical, use a small number of sequential integration tests sharing the exact serialized artifact output from the preceding boundary. The artifact bytes and stable IDs must remain identical across the handoff.

## 3. Required assertions

### Architect and canonical isolation

- The rich Forge cast does not trigger request-schema 400.
- The user correction reaches the mocked provider.
- Retry performs a request after an injected recoverable failure.
- Neither the correction nor model proposal mutates `forgeDraft` before explicit Apply.
- Apply closes the correct unknown once and preserves stable IDs.

### Map and placement

- The serialized Blueprint contains the reviewed compact map.
- Runtime starts at exact `startingNodeId`.
- Readable node label/description survives compilation.
- Directed exits match authored edges; no reverse edge appears without authorship.
- Expansion anchor is not an initial node or exit.
- The selected user character is at the opening node.
- The separated NPC is not co-located.
- The offstage character is absent from local presence.
- No unplaced cast member silently falls back into the player's room.

### Intent and pursuit

- The exact accepted player aim appears only in the typed player-baseline context.
- It creates no user pursuit, user activity opportunity, action, thought, or state mutation.
- The reviewed NPC pursuit seeds the existing HG1 authoring/runtime owner under the exact cast and node IDs.
- The No readable intent actor has review state `REVIEWED_NONE` and no fabricated pursuit.
- Legacy `goals` text does not independently authorize initiative.

### Compatibility and recovery

- Export snapshot becomes stale after any canonical draft/source-baseline edit and cannot be downloaded until refreshed.
- Reparsed artifact passes active Blueprint schema.
- Invalid identity/node/evidence variants fail before Engine start with field-addressable errors.
- A legacy Blueprint still loads through the explicit compatibility path without being falsely labeled Forge 1C-reviewed.
- Provider refusal data cannot enter draft, Blueprint, Engine context, story output, or ordinary exports.

## 7. Completion criteria

Forge 1C is ready for review only when:

- all four packets are implemented cumulatively;
- the real vertical artifact proof passes;
- the broad stabilization gate is clean;
- the Forge-produced artifact initializes the Engine at the reviewed node with exact placement;
- the accepted player aim remains sovereign read-only context;
- non-user pursuits/no-readable-intent states initialize correctly;
- the Architect correction and retry paths function;
- no provider failure data enters canon; and
- no unresolved production blocker is concealed as a deferred limitation.

If any criterion fails, report Forge 1C as incomplete and identify the owning boundary. Do not fall back to contextual ambiguity, placeholder topology, default co-location, or synthesized user aim merely to make export succeed.
